    Docker 与 Nginx 网站部署笔记

    1. Docker Compose 与端口映射

    compose.yaml 是容器编排配置文件，用来描述需要启动哪些服务以及运行参数。

    每个 Docker 容器都有独立的网络空间。宿主机端口和容器端口通过端口映射连通：

    ports:
  - "5432:5432"

    左边是宿主机端口，右边是容器端口。PostgreSQL 默认监听容器内的 5432 端口，因此常见写法是 5432:5432。

    生产环境的数据库端口

    数据库通常不需要对公网开放。生产环境可以只绑定本机回环地址：

    ports:
  - "127.0.0.1:5432:5432"

    开发环境为了方便调试可以使用 5432:5432，但这会绑定到所有网卡地址，容易被扫描。不要使用默认账号、弱密码或把密码直接写进公开仓库。

    Compose 服务之间通信

    同一个 Compose 项目中的服务会自动加入同一个网络，并且可以通过服务名互相访问，不需要为内部通信配置端口映射。例如 Spring Boot 连接名为 postgres 的数据库服务：

    jdbc:postgresql://postgres:5432/srams

    这里的 postgres 是服务名，Docker 内置 DNS 会把它解析到对应容器的 IP。容器 IP 可能变化，因此不要把它写死。

    2. 端口、防火墙与网络边界

    端口是操作系统区分网络服务的编号，范围通常是 0–65535。防火墙负责过滤进入主机的网络数据包；服务本身仍然需要正确配置监听地址和认证机制。

    部署时应尽量减少公网暴露的端口，只开放确实需要提供给用户访问的端口，并为数据库、管理后台等服务增加访问控制。

    3. Nginx 的作用

    Nginx 可以作为网站的统一入口和反向代理：

    • 用户通常只访问 Nginx 的 80/443 端口。
    • / 返回前端构建后的静态文件。
    • /api/ 转发到 Spring Boot 等后端服务。
    • Vue 等前端构建产物由 Nginx 直接托管。
    • HTTPS 证书配置在 Nginx，后端可以通过内网连接。
    • 多个后端实例可以由 Nginx 做负载均衡。

    4. location 与 proxy_pass

    location 用于匹配请求路径：

    location /api/ {
    proxy_pass http://127.0.0.1:8080;
}

    此时请求 /api/login 会转发为后端的 /api/login。

    如果 proxy_pass 末尾带斜杠：

    location /api/ {
    proxy_pass http://127.0.0.1:8080/;
}

    请求 /api/login 会去掉匹配到的 /api/，转发为后端的 /login。是否保留前缀取决于后端路由设计。

    对于 /api/login，location /api/ 比 location / 更具体，因此会优先匹配；location / 可作为默认规则。

    5. 常见 HTTP 状态码

    状态码 含义
    200 请求成功
    301 永久重定向
    302 临时重定向
    304 资源未修改，使用缓存
    400 请求格式错误
    401 未认证或 Token 无效
    403 已认证但没有权限
    404 找不到页面或接口
    500 后端程序发生错误
    502 Nginx 无法正常连接上游服务
    504 上游服务响应超时
